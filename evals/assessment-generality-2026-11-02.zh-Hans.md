### `packaged-browser-target`：使用已有浏览器测试目标

决策：可以继续，仅通过工具提供方给出的精确测试上下文或配置 ID、测试账号和本次测试拥有的标签页或窗口识别目标。无需 PID、开发构建或项目启动器。记录浏览器及工具提供方版本、上下文 ID、构建版本或 URL、工作区或显示器，以及观察的起止时间。只连接该上下文，绝不枚举或使用其他上下文。仅通过限定到该上下文的 API 执行已授权操作，再用 DOM 或辅助功能证据及覆盖操作的限时观察验证结果。如果连接导致激活，或目标范围变得不明确，就停止。只清理本次测试创建或明确拥有的标签页、页面或上下文资源，不关闭共享浏览器或用户上下文。如果修改了状态，只通过变更台账恢复能够证明归本次测试所有的修改。报告来源、操作、证据、有限的干扰观察覆盖范围、局限和清理结果。

### `navigation-only-acceptance`：只验收导航

决策：进行一次范围明确的功能检查，不检查完整控件矩阵。绑定精确且归本次测试所有的浏览器上下文，启动已准备好且带时间戳的观察器，仅使用文档规定的上下文定向导航或 DOM 操作，通过 Reports 导航一次。读取 DOM，验证预期 URL 或页面身份，以及所需的只读内容标记，并保留允许采集的 DOM 证据。在硬截止时间停止，记录该区间内前台应用、输入焦点、指针和工作区是否保持不变。不截图、不切换设置、不修改状态、不进行无关操作。除非导航改变了本次测试拥有的状态，否则无需恢复；保留用户上下文。分别报告功能验收和无干扰结果，包括分辨率和观察盲区。

### `existing-harness-observations`：复用执行工具已有观察

决策：可以。只要报告资源归属、时钟基准、截止时间、分辨率和盲区，执行工具带时间戳的限时记录及关联的工具输出引用，就能够支持其覆盖维度的结论，包括启动或连接、请求操作、前台应用、输入焦点、指针和工作区。不必为了存储证据而要求外部观察器或本地跟踪文件。对于这些干扰结论，无需额外插桩。如果目标定向输出尚未证明功能结果，只使用现有受支持 API，增加一次 DOM、辅助功能或实例定向截图结果检查。说明有限的采样区间，不推断采样间隙内的行为。在截止时间停止本次测试拥有的记录，并保留证据引用。

### `supported-os-script-route`：使用受支持的操作系统脚本路径

决策：不因命令名称拒绝该路径。根据同一应用及构建、操作系统、执行工具、显示器布局和操作下的文档与校准结果，评估具体命令。题设中的语义化窗口操作、匹配的校准、当前身份及显示器布局检查，以及限时观察，使该路径可以作为候选方案；无需修改应用或增加内置窗口放置参数。核验归本次测试所有的窗口及请求的显示器，只调用已批准的命令，然后用允许的定向证据验证窗口位置和操作结果。如果它激活应用、使用全局输入、定位不明确或证据与预期不符，就停止。其他命令仍禁止使用。记录路径及版本、校准范围、实际显示器布局、操作时间、观察、局限和清理结果。

### `shared-backend-state`：共享服务端状态

决策：不执行偏好写入。独立 Cookie 和浏览器存储只能隔离客户端上下文，不能隔离用户正常登录账号对应的服务端状态。该写入会修改已授权后台测试范围之外的工作数据；不会激活应用的 UI 自动化也无法解决数据范围违规。写入前停止，不先写入再恢复，因为共享状态可能被其他使用者读到、发生竞争或被并发修改。只有将任务缩小为只读检查后才继续。对于写入，需要专用测试账号或租户，或具有独立持久化及明确重置边界的一次性服务端测试夹具；然后重新评估授权，再运行限时验收。
